# 麦轮小车开发日志

参赛队伍：明月战队

本车为两台参赛小车中的第二台，采用麦克纳姆轮全向底盘，主控为 ESP32-S3，配两个舵机与独立设计的电源系统，整车由 PS2 手柄遥控，用于平层场地的快速机动与取放作业。

---

## 麦轮底盘与四轮驱动

### 功能描述

实现小车在场地内的全向移动，包括前进、后退、左右横移与斜向移动，并能够原地旋转调整车身朝向。

### 设计思路与选型

本车的任务集中在平整场地，机动效率比越障能力更重要。普通四轮差速底盘改变朝向必须先行驶、再转向，走位路径长；麦克纳姆轮通过在轮缘布置 45° 辊子，把轮子的驱动力分解出垂直于轮轴的分量，四个轮子协同即可在不改变车身朝向的前提下向任意方向平移。

驱动方案上，四个马达由 2 个电机驱动模块控制。四轮独立驱动是全向移动的前提——每个轮子的转速与方向都必须能被单独指定，任何一个轮子被联动都会破坏速度合成关系。

### 实现过程

ESP32-S3 根据手柄输入解算出四个轮子的目标转速与方向，通过两路驱动模块输出 PWM。轮子采用对角同向、相邻反向的布置，横移时对角轮同向转动、另一对角轮反向转动，两者速度分量叠加后得到垂直于车身的合力。

### 难点与解决

**斜向移动时车身漂移。** 麦轮的全向依赖四个轮子速度严格匹配，实际中四个马达的个体差异、轮子与地面的摩擦差异都会让合成方向偏离预期，表现为"打斜"。处理办法是实测标定：让小车分别执行直行与横移，测量实际轨迹与理论方向的偏差，再对四个轮子的速度系数做修正。

**辊子方向装反。** 麦克纳姆轮的辊子有旋向之分，一旦某个轮子装反，该轮的速度分量方向与其余三轮相反，合成后会表现为原地打转或无法横移。装配阶段对四个轮子的辊子旋向做了统一核对，并对每个轮子单独做正反转测试后再联调。

### 迭代优化

初版联调时先追求速度，横移与斜移在大占空比下打滑明显，轨迹偏差较大。降低横移与斜移的基础占空比、把加速过程做缓之后，轮子附着力跟得上速度变化，轨迹精度明显改善。

## 全向运动解算

### 功能描述

把手柄的平移与旋转指令实时分解为四个轮子的转速与方向，使小车能够连续、平滑地完成任意方向的运动。

### 设计思路与选型

麦轮的运动本质是一个速度合成问题：车体的期望运动可以分解为沿车身前后、左右两个方向的平移分量加上绕中心的旋转分量，四个轮子的转速是这三个分量的线性组合。解算放在 ESP32-S3 上完成，正是因为它需要在每个控制周期内实时计算四个轮子的输出，且计算频率要跟得上手柄输入的变化。

### 实现过程

控制流程分为三层：手柄输入解析出摇杆的归一化数值；归一化数值映射为车体期望的前后速度、左右速度与自转角速度；再按麦轮的几何关系叠加为四轮速度，做归一化处理后输出为 PWM 占空比。当某个轮子的计算结果超出可输出范围时，按比例缩放全部四个轮子的速度，保证方向正确、只损失速度，不会出现某个轮子被截断导致的轨迹畸变。

### 难点与解决

**多动作叠加时的输出饱和。** 同时推满前进与横移摇杆时，叠加后的轮速会超出电机能力上限。若简单截断，四个轮子的比例被破坏，小车走出的方向与手柄意图不一致。改为等比例缩放后，方向保持正确，操作手感也更符合直觉。

**摇杆死区导致的静止漂移。** 摇杆回中后存在零点偏差，解算结果不为零，小车会缓慢爬行。在输入层设置死区，把中位附近的小幅输入归零，解决了静止漂移。

### 迭代优化

初版把解算逻辑直接写在主循环里，手柄、解算、输出耦合在一起，调整任一部分都要改动整体。重构后把输入解析、运动解算、电机输出分为三层，各自独立，后续修正速度系数时只改解算层，不影响其他模块。

## 双舵机分级配置

### 功能描述

为车上两处执行机构配置两个舵机，分别承担带负载保持角度的动作与小角度轻负载动作。

### 设计思路与选型

两处执行机构的负载差别很大：一处在动作后需要带负载停在某个角度，受外力时不能偏移；另一处只需完成小角度的轻载摆动。如果统一按最重负载选型，另一处会背上不必要的重量和电流开销——大扭矩舵机自重大，转动时电流也高，对本就紧张的电源余量是额外负担。

因此采用分级配置：

| 需求             | 选用     | 理由                           |
| -------------- | ------ | ---------------------------- |
| 带负载、需保持角度、承受外力 | MG996R | 金属齿轮，扭矩约 11 kg·cm，负载能力强，定位稳定 |
| 轻负载、小角度、空间受限   | SG90   | 体积小、重量轻，塑料齿轮足以应对轻载           |

这也解释了为什么不选清一色的大扭矩方案：小型舵机扭矩约 1.8 kg·cm，用作轻载动作完全够用，而把它的位置换成大扭矩舵机会带来重量与电流的双重浪费；反过来，把需要带载保持的位置交给塑料齿轮的小舵机，则有扫齿和角度被外力带走的风险。

### 实现过程

两个舵机均由 ESP32-S3 输出 PWM 控制，转角按各自机构的行程单独标定，避免转动到机械限位造成堵转。舵机供电取自降压模块，与主控逻辑电路同源但独立走线，减少动作时对逻辑电路的干扰。

### 难点与解决

**舵机动作引起主控电压波动。** 大扭矩舵机启动瞬间电流较大，若与主控共用细走线，会把电压拉低。通过把舵机供电与主控供电在走线上分开、并在舵机端并联电容，抑制了瞬态压降。

**两个舵机的动作时序冲突。** 两个舵机若同时动作，峰值电流叠加会超过电源余量。在控制上做了动作排队，让两个舵机的动作错开执行，把峰值电流控制在电源能力之内。

### 迭代优化

初版两个舵机直接由开发板板载稳压供电，同时动作时会出现复位。改由降压模块单独供电、并在软件上错开动作时序后，问题消除，动作也更连贯。

## 电源系统设计

### 功能描述

为整车主控、四个马达、两个舵机提供稳定的分级供电，保证各电压域互不干扰、电压保持在器件要求范围内。

### 设计思路与选型

本车的用电部件分成三类，电压需求各不相同：主控与传感器需要稳定的低压逻辑电源；舵机需要按其额定电压供电，且启动电流大；而电池的输出电压在放电过程中会持续下降，既高于逻辑电路的要求，又可能低于某些负载所需电压。

单靠电池直供无法同时满足这三类需求，因此把电源拆成三条路径：

| 模块   | 作用                             |
| ---- | ------------------------------ |
| 降压模块 | 把电池电压降到主控与逻辑器件的可用范围，并保持稳定      |
| 升压模块 | 为需要较高电压的负载提供稳定输出，避免电池电压下降后输出不足 |
| 电池模块 | 作为整车能量来源，统一管理与更换               |

降压与升压并存的原因在于：电池电压在满电与放电末期差别明显，只靠降压，低压时部分负载得不到足够电压；只靠升压，逻辑电路又会超出耐压。两条路径各自负责一个方向，才能在整个放电区间内保持各路电压稳定。

### 实现过程

电池模块输出分别接入降压模块与升压模块，降压输出供主控与舵机，升压输出供高压负载，四个马达通过驱动模块直接取自电池。三条路径在电源入口处分开走线，避免大电流回路的压降叠加到逻辑回路上。

### 难点与解决

**舵机与马达共用电池时的电压跌落。** 四个马达同时启动或堵转时，电池端电压被瞬时拉低，会连带影响升降压模块的输入，造成主控复位。解决办法是在模块输入端加大容量电容做能量缓冲，并把马达的大电流回路与逻辑回路在走线上完全分开，避免共用同一段导线。

**升压模块的纹波。** 升压电路在高负载下输出纹波偏大，会对主控造成干扰。通过增加输出滤波、并把升压模块的走线远离信号线，降低了干扰。

### 迭代优化

初版电源全部接在面包板上，走线随意，大电流路径与信号路径交叉，出现过随机的复位与舵机误动。改为洞洞板焊接并重新规划电源分区后，供电稳定性得到根本改善。

## 洞洞板电路改造

### 功能描述

把驱动模块、电源模块与整车走线从面包板迁移到洞洞板上焊接固定，提高电路在小车行驶振动下的可靠性。

### 设计思路与选型

面包板靠金属弹片夹持元件引脚与跳线，在静态调试时方便，但小车行驶时存在持续振动，弹片与引脚之间会产生微小位移，接触电阻随之变化。这种失效的特点是偶发、间歇、不可复现：小车静止时一切正常，一动就可能出现某个通道失控或主控复位，排查时往往怀疑代码，实际是接触问题。

考虑到本车有四路电机驱动、两路舵机与三个电源模块，插接点数量多，任何一个点接触不良都会影响整车，因此决定改用焊接方式固定。洞洞板上的焊点是冶金连接，不受振动影响，走线也可以按电流大小规划宽度与路径。

### 实现过程

按功能分区布置模块：大电流的马达驱动与电源模块集中在板子一侧，信号与主控接口布置在另一侧，减少大电流回路对信号的回耦。电源走线加宽，信号线尽量短且避免与电源线平行走线。所有模块用排针或焊盘固定，接口处做应力释放，避免线缆受力直接传到焊点。

### 难点与解决

**焊接后的可维护性下降。** 焊死之后更换模块必须拆焊，因此在下板之前先做完整的功能验证，并对易损模块预留插座而不是直接焊死，兼顾可靠性与可更换性。

**走线规划。** 洞洞板空间有限，模块数量多，初版布局导致电源线与信号线多次交叉，干扰明显。重新规划后把电源入口固定在板子一角，按"电源在外、信号在内"的层次布线，交叉大幅减少。

### 迭代优化

改造完成后，行驶中的偶发失控现象消失，之前难以复现的故障不再出现。后续又对焊点做了补强与绝缘处理，避免长期振动下焊点开裂。

## PS2 遥控与主控平台

### 功能描述

通过 PS2 手柄遥控整车运动与两个舵机的动作，由 ESP32-S3 完成信号解析、运动解算与指令分发。

### 设计思路与选型

主控选择 ESP32-S3。本车需要在每个控制周期内完成手柄数据解析、麦轮运动解算与四路 PWM 更新，计算量明显高于单功能小车；ESP32-S3 的主频与双核结构可以把手柄通讯与运动解算分配到不同任务中，避免相互阻塞，GPIO 数量也足以覆盖四路电机、两路舵机与手柄接口。

与 STM32 方案相比，ESP32-S3 在多任务调度与后续扩展上更灵活；与资源较少的开发板相比，它能保证解算频率稳定，不会因计算占用导致 PWM 输出抖动。

### 实现过程

PS2 接收器与 ESP32-S3 通讯，手柄数据解析为归一化摇杆值与按键状态；摇杆值进入运动解算层生成四轮速度，按键触发舵机动作。通讯与解算分开运行，输出层统一更新 PWM，保证同一控制周期内四个轮子的速度是同步下发的。

### 难点与解决

**手柄延迟与运动解算争抢资源。** 初期手柄读取与解算在同一循环中串行执行，解算耗时波动会直接拉长手柄读取间隔，操作手感时快时慢。改为把手柄通讯放在独立任务中持续读取、主循环只取最新值后，输入延迟稳定下来。

**通道映射与调试效率。** 四路电机、两路舵机的通道与引脚对应关系复杂，接线错误时现象不直观。通过在软件中建立通道映射表、并逐个通道单独测试，把硬件接线问题与逻辑问题分离排查。

### 迭代优化

初版所有逻辑集中在一个任务里，随功能增加响应变慢。重构后按"通讯—解算—输出"分层，各层独立运行，后续调整运动参数不再影响通讯时序。

## 结构抗跌落设计

### 功能描述

整车在 180 mm 高度、底面朝下的自由跌落条件下不发生零件脱落，保证运输与意外碰撞后的结构完整性。

### 设计思路与选型

结构件以 PLA 打印为主。PLA 刚性好、打印稳定，适合做模块支架，但抗冲击能力有限，冲击载荷集中时容易在层间开裂。设计阶段即按冲击工况考虑：连接处增加加固筋，把集中受力分散为面受力；模块以螺丝固定在主结构上而非悬空安装；对易位移的零件设置限位。

### 实现过程

机架在关键节点加三角加固筋，承力路径尽量落在底盘上；洞洞板与模块用螺丝锁固，避免仅靠打印件配合面定位；电源与电池做限位挡边，防止跌落时窜动。

### 难点与解决

**跌落后固定点松动。** 首次测试发现部分螺丝孔位出现松动，原因是冲击能量直接作用在螺纹孔上。在螺丝与打印件之间增加紧固垫片分散压应力、并重新整定锁固力矩后，孔位不再松动。

### 迭代优化

改进后复测，180 mm 跌落后结构完好、无零件脱落。后续把较重的模块下移，进一步降低重心，减少跌落时的翻转力矩。
